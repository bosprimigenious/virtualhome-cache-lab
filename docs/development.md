# 开发步骤与验收

## 1. 本地基线（当前阶段）

运行 README 命令。检查六组结果 requests 一致，decision_calls + reuse_events == requests，valid_reuse + stale_reuse == reuse_events。完整保留数据清单差异，不擅自合并未引用任务。

本地课程 ZIP 含 60 个任务文件，但原 sessions.json 的 5 个会话只引用 40 个任务，与指导书的“5×12”不一致。另有 5 处会话内图不连续边界。先按原清单评测 40 个；向老师核对正式划分后新增版本化配置，不覆盖旧结果。先明确会话连续性再补任务；反过来随意拼接会让跨任务缓存基于错误世界状态。

## 2. 真模型（成员 B）

新增可配置的 OpenAI 兼容接口。密钥只走环境变量，配置记录模型完整名称、版本、服务端、temperature=0、max_tokens、提示模板版本。先用一个会话测试 JSON 输出，再扩展到全会话。保存每次请求的输入哈希、输出、错误、延迟与角色（决策或评估）。测试失败和格式错误必须计数，不回退 gold 冒充模型回答。不在此阶段自动购买服务或调用付费接口。

## 3. 依赖与评测（成员 A）

输出逐事件 trace：会话、任务、步骤、查询键、缓存创建步、复用/重算原因、输入依赖、预测和 gold 正确性。新增被抓取后角色移动、容器移动、目标新增/删除、同名物体和状态恢复等边界测试。

对每次判定记录缓存答案是否仍匹配当前 gold，形成漏失效/误失效统计。模型本身生成错误要与缓存过期分开。fine/coarse 使用相同真实模型输入模板，避免粒度比较被提示变化混淆；当前 Mock 投影对比仅验证失效机制。

## 4. 正式对照（共同完成）

同数据、同顺序、同模型、同提示、同解码参数运行 none、fixed k=3/5/10、dependency fine/coarse。报告正确复用、错误复用、模型调用、真实推理耗时与端到端耗时；保留所有失败。至少分析抓取关系、无关状态变化、固定窗口过期各一个案例。

最终门禁：数据划分核实；真实模型全策略实验；事件级审计；失效准确率与粒度消融；两位成员复跑；官方模板报告与配置/原始结果齐全。任何一项缺失均为 NOT READY。
